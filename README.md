# Items Description

Небольшой FastAPI-сервис для генерации **черновиков SEO-карточек промышленных товаров** на основе переданного JSON и LLM. Проект демонстрирует структурированные ответы модели, проверки качества, ограниченные повторы и явные предупреждения.

**Реализованы:** `GET /healthz`, `POST /generate`, асинхронный LLM-клиент, Structured Outputs, валидация, тесты. Реальные результаты LLM на выбранных товарах будут добавлены после проверки с конкретной моделью.

## Возможности

- Получает название товара, производителя, характеристики и исходное описание.
- Убирает неизвестные значения характеристик и сообщает об отсутствующих данных.
- Запрашивает у LLM четыре поля: `seo_title`, `seo_description`, `search_queries` и `commercial_block`. Поставщик LLM должен поддерживать strict JSON Schema.
- Проверяет: заголовок 1–70 символов; описание 800–1200 символов; 3–5 уникальных непустых поисковых запросов; непустой коммерческий блок.
- Отмечает некоторые неподтверждённые числа, размерности, классы IP и коммерческие утверждения.
- При исправимых нарушениях делает **до двух повторных запросов** (три вызова LLM суммарно).
- Возвращает технические характеристики **из входных данных, а не из результата LLM**.
- При явных признаках подмены инструкций в данных не вызывает LLM, а возвращает `needs_review`.

## Требования и установка (Windows PowerShell)

Python 3.12+ и pip. Для реальной генерации нужен LLM API с поддержкой структурированного вывода; для тестов API-ключ не требуется.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
```

Если виртуальное окружение уже создано, достаточно активировать его и установить зависимости.

## Настройка LLM

```powershell
Copy-Item .env.example .env
```

Заполните `.env` (пример для OpenAI-совместимого API):

```dotenv
LLM_MODEL=gpt-4o-mini
LLM_API_KEY=YOUR_API_KEY
LLM_BASE_URL=
LLM_MAX_TOKENS=2048
LLM_TIMEOUT_SECONDS=30
```

- `LLM_MODEL` — имя модели у выбранного провайдера.
- `LLM_API_KEY` — ключ API; не коммитьте настоящий ключ.
- `LLM_BASE_URL` — необязательный адрес OpenAI-совместимого сервера. Для локального сервера с этим параметром ключ может быть пустым.
- `LLM_MAX_TOKENS` — максимум токенов ответа; слишком маленький лимит может оборвать JSON.
- `LLM_TIMEOUT_SECONDS` — таймаут одного обращения.

Пример локального URL: `http://localhost:11434/v1`. **Совместимость зависит от модели и сервера:** реализация использует `chat.completions.parse()` с Pydantic `response_format`, и не каждый OpenAI-совместимый сервис поддерживает строгую JSON-схему.

Для генерации требуется непустой `LLM_MODEL` и либо `LLM_API_KEY`, либо `LLM_BASE_URL`. После правки `.env` перезапустите сервер. Для входных данных, возвращающих `insufficient_data` или заблокированных фильтром, LLM не вызывается и настройка не нужна.

## Запуск

```powershell
python -m uvicorn app.main:app --reload
```

- `GET http://127.0.0.1:8000/healthz` — `{"status":"ok"}`.
- `POST http://127.0.0.1:8000/generate` — генерация карточки.
- [Swagger UI](http://127.0.0.1:8000/docs) — интерактивная проверка запросов.
- [OpenAPI JSON](http://127.0.0.1:8000/openapi.json).

### Пример 1: блок питания

Иллюстративный входной JSON на основе тестовых данных проекта (не технический паспорт):

```json
{
  "name": "БП15Б-Д2-24",
  "manufacturer": "ОВЕН",
  "specs": {
    "Выходное напряжение": "24 В",
    "Выходной ток": "0,63 А"
  },
  "description": "Одноканальный блок питания."
}
```

### Пример 2: манометр с неполной информацией

```json
{
  "name": "ТМ-510Р.00",
  "specs": {
    "Диапазон": "0–2,5 МПа",
    "Класс точности": "данных нет для выбранной модификации"
  },
  "description": "Манометр."
}
```

Во втором примере класс точности не считается известной характеристикой. В результате `missing_fields` будет содержать `specs.Класс точности` и `manufacturer`. Программа не должна дополнять эти поля догадками.

**Отправка из PowerShell:** сохраните любой пример в `product.json` (UTF-8), затем выполните:

```powershell
$json = Get-Content .\product.json -Raw -Encoding UTF8
$body = [System.Text.Encoding]::UTF8.GetBytes($json)
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/generate" -ContentType "application/json; charset=utf-8" -Body $body
```

Либо откройте `/docs`, выберите `POST /generate` → **Try it out** и вставьте JSON.

### Пример воспроизводимого ответа без LLM

Для запроса `{"name": "АНТ-1", "manufacturer": "ОВЕН"}` сервис возвращает HTTP 200 и следующий ответ, даже если LLM не настроена:

```json
{
  "status": "insufficient_data",
  "seo_title": null,
  "seo_description": null,
  "characteristics": {},
  "search_queries": [],
  "commercial_block": null,
  "missing_fields": ["description", "specs"],
  "warnings": [
    "Недостаточно данных для генерации: нужны характеристики или описание."
  ]
}
```

Примеры SEO-текстов, якобы полученных от реальной LLM, здесь намеренно не выдумываются. Они будут добавлены после фактических испытаний.

## Статусы и HTTP-ответы

Структура `GenerationResponse` включает `status`, четыре SEO-поля, `characteristics`, `missing_fields` и `warnings`.

| Значение `status` | Значение |
| --- | --- |
| `generated` | Текст прошёл реализованные формальные и эвристические проверки; **это не гарантия полной достоверности**. |
| `needs_review` | Найдены замечания или признаки подозрительного ввода; нужна ручная проверка. |
| `insufficient_data` | Нет ни полезных характеристик, ни описания; LLM не вызывается. |

| HTTP-код | Значение |
| --- | --- |
| `200` | Обработанный результат с одним из статусов выше, в том числе `needs_review`. |
| `422` | Неверные типы/структура JSON, отсутствующее название или дополнительные поля. |
| `502` | Ошибка LLM API, отказ модели или непригодный структурированный ответ. Подробности ошибки провайдера наружу не возвращаются. |
| `503` | Для генерации не заданы обязательные настройки подключения к LLM. |

### Проверки и ограничения безопасности

- **Разделение ответственности:** LLM создаёт только SEO-тексты, характеристики берутся из предварительно обработанного входа. Истинность самих исходных данных должна быть подтверждена поставщиком или документацией.
- **Structured Outputs:** проверяется формат полей, но не истинность и не длина текста. SEO-ограничения контролируются валидатором.
- **Повторы:** ошибки валидатора возвращаются модели для новой генерации полного результата; максимум два повтора. Если они не помогли — `needs_review`, без молчаливого обрезания текста.
- **Prompt injection:** явные попытки подмены ролей и инструкций фильтруются до вызова LLM; выход также проверяется. Это **не универсальный детектор**: возможны обходы и ложные срабатывания.
- **Фактическая проверка:** сравниваются некоторые числа, единицы измерения, IP-рейтинги и упоминания гарантии, наличия, сертификатов, доставки, скидки или цены. Смысловые противоречия могут быть пропущены, поэтому `generated` не означает независимое подтверждение каждой фразы.
- **Область проекта:** нет БД, очереди, фронтенда, веб-поиска и внешней базы подтверждённых характеристик.


## Локальные испытания через Codex CLI (без OpenAI API-ключа)

Это **дополнительный вариант для ручного тестирования на собственном ПК**. Codex CLI запускается как отдельный процесс через Python и использует уже выполненную авторизацию ChatGPT. Использование зависит от доступности Codex и лимитов учётной записи; это не универсальная замена API для продакшена.

1. Установите Codex CLI и проверьте авторизацию:

   ```powershell
   codex --version
   codex login status
   ```

   Если авторизации нет — выполните `codex login`.

2. В локальном `.env` переключите бэкенд:

   ```dotenv
   LLM_BACKEND=codex_cli
   LLM_CODEX_MODEL=
   LLM_CODEX_TIMEOUT_SECONDS=180
   ```

   API-ключ не требуется. Пустой `LLM_CODEX_MODEL` означает модель Codex по умолчанию. При наличии локальных настроек `LLM_MODEL` и `LLM_API_KEY` они **не используются** в этом режиме.

3. Запустите приложение (`python -m uvicorn app.main:app --reload`) и отправьте один товар через Swagger UI на `POST /generate`. Запрос может оказаться дольше обычного API: Codex запускается заново на каждый запрос, а при нарушении требований возможны два дополнительных запуска.

**Границы доступа:** CLI запускается из временной папки, с `--sandbox read-only`, `--ephemeral`, `--ignore-user-config` и `--skip-git-repo-check`; рабочую папку проекта он не получает как cwd. Модель получает текст товара только через stdin, а итог считывается из `--output-last-message` с проверкой Pydantic. Аргументы ограничивают доступ к файлам, но режим read-only **не гарантирует отсутствие сетевых обращений**; локальные конфиденциальные данные без отдельного анализа отправлять не следует. Не используйте этот адаптер на публично доступном эндпоинте: входящие запросы могут расходовать лимит ChatGPT.

Наличие `--output-schema` подтверждается документацией Codex; если установленная версия CLI не поддерживает нужный аргумент, обновите её. Реальная совместимость пока не проверена: тесты адаптера подставляют процесс, не вызывая Codex.

## Проверки кода

```powershell
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
python -m pyright
```

Тесты используют подставную LLM, не делают платных запросов и покрывают схемы, ограничения, повторные попытки, примеры инъекций и поведение HTTP API. **Тесты с моками не подтверждают качество ответов настоящей модели и её устойчивость к prompt injection.**
